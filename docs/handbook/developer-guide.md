# Developer and maintainer guide

## Locate the right layer

Use [the architecture](architecture.md) before editing. CLI wrappers parse and
perform IO; reusable behavior belongs in `controlplane/`. Customer execution
must remain independent of the heavy model-extraction stack.

Read [AGENTS.md](../../AGENTS.md), [CLAUDE.md](../../CLAUDE.md),
[contribution rules](../../docs/CONTRIBUTING.md) and the local coordination
board. Historical plans do not make an unbuilt capability current.

## Work in a separate checkout

Use a topic worktree, inspect the shared board, declare ownership and preserve
other sessions' tracked and untracked work. Stage named files only. Local
review archives and generated outputs are not automatically publication inputs.

The [coordination protocol](../../COORDINATION.md) explains status and path
claims. A board claim is advisory operational state, not authentication.

## Before a statistical change

State the quantity, sampling unit, selection procedure and intended guarantee.
Identify old records and downstream consumers that use the existing semantics.
A changed estimator needs versioning and an explicit compatibility decision.

Do not silently rerun frozen results with a new method and replace their
bytes. A historical bug can remain visible in the historical artifact while
new issuance uses a repaired protocol.

Read-only areas and closed-study boundaries in the repository instructions
remain in force. A documentation finding is not automatic authorization for
a production statistical repair.

## Adding a command or schema

Keep the parser thin and add behavior in the library. Define input errors,
normal refusal behavior, output publication and replay semantics together.
A record that cannot be interpreted or checked later is an incomplete interface.

Exercise the real installed command, not only imports from the source tree.
Update the parser-derived reference and relevant workflow documentation.
Add a smoke/wiring check and tests for meaningful failure cases.

For a new record version, specify which old fields remain readable, which
decisions can still be relied on, and what is UNVERIFIED. Compatibility is
more than accepting old JSON syntax.

## Adding a scientific claim

A new README-table artifact must be classified in the reviewed family registry.
Document source data, writer, interpretation, reproduction requirements and
limits. The audit refuses an unclassified or ambiguously referenced artifact.

A clean source flag, checksum or matching value is not sufficient scientific
support. Explicitly identify whether a result is observed, simulated, authored,
historical, exploratory or a hypothesis.

Claim labels should name their population and quantity. Do not describe a
Monte Carlo success proportion as guaranteed performance or a challenge-set
precision as production precision.

## Generation ordering

Commit producing code and declarations first. Generate a new receipt from
clean source into a new destination. Commit that receipt separately with
its source revision and scope.

The collection inventory is generated by
[the inventory script](../../scripts/refresh_test_inventory.py). It reports
collection, not passing execution. Refresh it when meaningful new tests change
the count, and preserve that distinction in the README.

## Documentation source of truth

- Parser help comes from the CLI parser.
- Selected library contracts come from source inspection.
- The claim pages render the retained audit and reviewed family registry.
- The final notebook discussion comes from [its Markdown source](discussion-cell.md).
- The preprint's canonical source is LaTeX under `paper/`; numeric macros come
  from retained evidence.

Manual chapters explain concepts, experiments and procedures. They must not
upgrade a source's interpretation merely to make a result sound stronger.

## Editing generated files

Regenerate the claim ledger using the declared receipt:

```shell
python scripts/audit_documentation.py --render
```

The notebook builder compiles its code cells before writing output:

```shell
python scripts/build_notebooks.py
```

After a discussion-only change, verify that all preceding cells and outputs
are identical. Generating a notebook is not executing model inference.

The paper build retains its source/toolchain and validates the resulting PDF.
Do not edit a PDF to repair a scientific number; change the reviewed source or
underlying artifact appropriately and rebuild.

## Documentation review

Check the following:

1. A newcomer can find a supported first workflow.
2. Each command is either executable with retained examples or explicitly
   requires user-supplied inputs.
3. Relative links resolve on GitHub and in the built handbook.
4. Current behavior is distinguished from old plans.
5. Every numerical result has an evidence reference.
6. An interpretation is not presented as an observed causal mechanism.
7. Known adverse results and open issues remain visible.
8. Publication status and archival metadata are accurate.

## Commit and release discipline

Keep source/tooling, generated evidence, explanatory chapters, notebook changes
and rendered publication artifacts in reviewable commits. Use conventional
commit subjects and record numerical changes and provenance in their bodies.

Run the focused checks, static analysis, documentation build and required
release checks. Merge the completed topic with its history, push the verified
main and record the exact CI result. Never substitute a collection count for
a completed suite.

The [phase report](../../reports/PHASE-55.md) records this documentation effort.


## Reproduce and check every generated reference

The [source declaration](reference-sources.json) names the retained claim audit
and API modules. Regenerate the claim ledger, family catalog, command help and
selected API reference together:

```shell
python scripts/audit_documentation.py --render-references
python scripts/audit_documentation.py --check-generated --links-all
```

The checker reports missing and stale pages without rewriting them. Run it after
changing a parser flag, a selected function signature/docstring, a claim receipt
or the family registry. CI checks the same contract. The older `--render` option
continues to regenerate only the two claim pages.

The [layout guide](repository-layout.md) explains current manuals, historical
records and directories that should not be relocated casually. Read the
[closure review](../../reports/PHASE-56.md) for later branch/worktree findings;
Phase 55 remains the record of the original handbook/preprint build.
