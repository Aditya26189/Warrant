# A04 controlled evidence execution — engineering plan v1

The 19 October 2026 sustained execution mandate authorizes evidence provision and
research engineering under A04, not a scientific amendment or eligibility review.
The original exposed custodian is the evidence provider. No independent reviewer
or separate semantic restriction checker is invented by this workflow.

Mechanically reconstruct all 372 work requests and 389 members from the locked
A04 inventory if no authenticated fresh-reviewer return is available. Start every
request with the same T/B/P/L, bibliography, identity, version, sentinel and access
requirements. Do not import previous decisions or indicate which works were
formerly included/excluded. Preserve the original intake archive and every older
research artifact unchanged.

Acquisition uses only frozen member URLs, explicit captured arXiv versions and
official arXiv/ACL hosts. Reuse hash-verified raw cache bodies and original access
timestamps. Never reuse old masked displays. Bounded retries and fallback between
HTML/PDF for the same explicit version are operational changes only. Missing,
withdrawn, malformed or unverifiable sources remain explicit exceptions. An
explicit-version response is distinct from final publisher-preference resolution.

All unrestricted source bodies, parsed text, broader method proposals and errors
stay in an ignored custodian quarantine. Immutable per-member receipts and atomic
checkpoints allow interruption recovery; a mismatched checkpoint is quarantined,
not silently repaired or treated as completed. Re-running processing must produce
byte-identical source-derived evidence, separately from actual acquisition times.

Release paths:

1. **Bibliography:** project identifiers and captured date/version fields from
   hash-locked metadata; attach primary-response hashes and access statuses.
   Explicitly distinguish verified captured preprint versions, body self-links,
   retrieval transport and unresolved final protocol-preferred versions.
2. **Closed-grammar method evidence:** retain only exact source sentences in
   structurally established method/data/threat-model sections. Reject abstract,
   results, tables, figures, captions, related-work/conclusion/reference ancestry,
   adjoining outcome prose, malformed/truncated HTML and unknown attribution.
   The entire normalized sentence must match a finite method-only language; no
   unrestricted slot or numeric masking is allowed. A separate verification pass
   reopens the raw body and reconstructs section, locator and sentence before
   checking the full grammar. This is an automated restriction check, not an
   independent human/AI semantic attestation or an eligibility judgment.
3. **Other method evidence:** prepare proposals in quarantine, with source
   context and precise locators. They require a separately established semantic
   restriction checker before any reviewer release. PDF extraction alone cannot
   establish reading order or section attribution; PDF proposals are never
   automatically released. Do not send these quarantined proposals to the fresh
   eligibility reviewer. If that checker is unavailable, continue the complete
   acquisition/integrity work and report that actual external dependency.

The restricted evidence supplement is separate from the unchanged original intake.
It includes all-work/member coverage, verified evidence only, receipts, hashes,
safe exception codes and an offline verifier. No raw text, quarantine paths, prior
judgments, private human sheets or source-result displays enter its allowlist.
Unavailable method evidence is not a domain exclusion. A partial fact or a methods
term is not proof that all eligibility requirements are met.

Keep Q002's withdrawn latest v2 and its inaccessible source history separate from
supplemental v1; never substitute v1. Keep Q026/Q153 distinct pending study-unit
adjudication. D01 remains one work and D02 distinct. Prepare sentinel identity
commitments without adding exclusions. Original eligibility rules, sources, cap,

Final reporting separates source availability, exact-version evidence, unresolved
preferred versions, generated proposals, restriction-verified method evidence,
transfer readiness, actual delivery and actual independent review. If review or
necessary semantic checking cannot be established, FRAME_BLOCKED remains correct.
