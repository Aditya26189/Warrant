# Feasibility gate: released final records, with narrower claims

29 October 2026. Exploratory discovery; no bulk comparison has run.

The official release is pinned to
[`572b2614be2c0cb2527e14f5b1e4026f1072e6c1`](https://huggingface.co/datasets/harborframework/terminal-bench-2-leaderboard/tree/572b2614be2c0cb2527e14f5b1e4026f1072e6c1).
Nonrecursive discovery inventories identify submission/job directories, configs,
named final trial directories and aggregate reward/exception indexes. Canonical
counts and source hashes will be generated by the committed inventory program.

The ten deterministic structural discovery jobs in U002 include reward-bearing
exceptions and null-reward counters. One unfinished job's summary counts more
final trials than its released trial directories. These are discovery exposure,
not representative estimates or proof that any original execution was absent.
All inspected trial records carry task names, UUIDs, Git task IDs and checksums;
the task IDs match the official TB2 reference revision in these discovery cases.
The full census must still establish compatibility and reconcile contradictions.

**Gate B passes for a released-final-record accounting study.** It does not pass
for complete pre-release execution history, retry selection, or a corrected
official leaderboard. The primary population is the named released final
records; aggregate-only names and configuration cardinalities are audited in
separate ledgers rather than silently added as unscored executions.

The [official card](https://huggingface.co/datasets/harborframework/terminal-bench-2-leaderboard/blob/572b2614be2c0cb2527e14f5b1e4026f1072e6c1/README.md)
requires a minimum of five trials and permits multiple jobs. Configs can request
other repetition counts or task subsets. Neither the minimum nor random suffixes
establish exact planned trial IDs. Mutable registry references and local dataset
paths require explicit qualification when checking declared task cardinalities.
No `planned_slots.csv` will be invented.

Two dated official Harbor versions document null-as-zero final-record means:
[January mean](https://github.com/harbor-framework/harbor/blob/1c0f38644b94c2a9a5fa4a8b77667d8175d0869e/src/harbor/metrics/mean.py)
and [May mean](https://github.com/harbor-framework/harbor/blob/5a22a1dd4cc42fff8418bcb1e796ceb3624df931/src/harbor/metrics/mean.py).
The [job counter code](https://github.com/harbor-framework/harbor/blob/1c0f38644b94c2a9a5fa4a8b77667d8175d0869e/src/harbor/models/job/result.py)
separately counts scored records and exceptions. They can overlap. Submitted
records lack an exact harness-version field, so reproducing an artifact's actual
metric remains necessary before attributing behavior to a particular version.

The [official integrity policy](https://www.tbench.ai/news/leaderboard-integrity-update)
permits rescoring and removals. A versioned historical website importer and
row-specific adjudication ledger have not been recovered. Raw job means cannot
be called the current displayed official score. Website reproduction is marked
unavailable; artifact-native reproduction is supported and precedes comparison.

HAL is not invoked: the primary candidate supports the narrower final-release
question, while HAL's cleaned scored rows do not repair missing attempt-history
evidence. No additional benchmark search is authorized by an alarming example.

The strongest threat to publication value is prior overlap with issue 2246 and
existing denominator-bound work. A full reconciliation may still yield REPORT.
